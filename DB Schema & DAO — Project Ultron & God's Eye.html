1. SQL DDL

PRAGMA journal_mode = WAL;
PRAGMA foreign_keys = ON;
PRAGMA synchronous = NORMAL;   -- safe durability/perf tradeoff under WAL

-- ─────────────────────────────────────────────────────────────
-- network_assets — every device God Eye's ARP radar has ever seen
-- ─────────────────────────────────────────────────────────────
CREATE TABLE IF NOT EXISTS network_assets (
    id              INTEGER PRIMARY KEY AUTOINCREMENT,
    ip_address      TEXT    NOT NULL UNIQUE,
    mac_address     TEXT    NOT NULL,
    hostname        TEXT,
    is_authorized   INTEGER NOT NULL DEFAULT 0 CHECK (is_authorized IN (0, 1)),
    first_seen      TEXT    NOT NULL DEFAULT (STRFTIME('%Y-%m-%dT%H:%M:%fZ', 'NOW')),
    last_seen       TEXT    NOT NULL DEFAULT (STRFTIME('%Y-%m-%dT%H:%M:%fZ', 'NOW'))
);

CREATE INDEX IF NOT EXISTS idx_assets_mac ON network_assets (mac_address);
CREATE INDEX IF NOT EXISTS idx_assets_authorized ON network_assets (is_authorized);

-- ─────────────────────────────────────────────────────────────
-- telemetry_events — raw sensor output, pre-AI-analysis
-- ─────────────────────────────────────────────────────────────
CREATE TABLE IF NOT EXISTS telemetry_events (
    id              INTEGER PRIMARY KEY AUTOINCREMENT,
    source_module   TEXT    NOT NULL CHECK (
                        source_module IN ('RADAR', 'CANARY', 'HONEYPOT', 'AUTH_LOG')
                    ),
    suspicious_ip   TEXT,
    raw_payload     TEXT    NOT NULL,      -- JSON blob, validated at the app layer
    correlated      INTEGER NOT NULL DEFAULT 0 CHECK (correlated IN (0, 1)),
    timestamp       TEXT    NOT NULL DEFAULT (STRFTIME('%Y-%m-%dT%H:%M:%fZ', 'NOW'))
);

CREATE INDEX IF NOT EXISTS idx_telemetry_ip ON telemetry_events (suspicious_ip);
CREATE INDEX IF NOT EXISTS idx_telemetry_timestamp ON telemetry_events (timestamp);
CREATE INDEX IF NOT EXISTS idx_telemetry_uncorrelated ON telemetry_events (correlated)
    WHERE correlated = 0;

-- ─────────────────────────────────────────────────────────────
-- incidents — Ultron Core's reasoning output over correlated events
-- ─────────────────────────────────────────────────────────────
CREATE TABLE IF NOT EXISTS incidents (
    id              INTEGER PRIMARY KEY AUTOINCREMENT,
    incident_uid    TEXT    NOT NULL UNIQUE,   -- e.g. UUID4, generated app-side
    risk_score      INTEGER NOT NULL CHECK (risk_score BETWEEN 0 AND 100),
    severity        TEXT    NOT NULL CHECK (
                        severity IN ('LOW', 'MEDIUM', 'HIGH', 'CRITICAL')
                    ),
    mitre_tactic    TEXT,                       -- e.g. "Credential Access"
    mitre_id        TEXT,                       -- e.g. "T1110"
    summary         TEXT,                       -- plain-English agent explanation
    status          TEXT    NOT NULL DEFAULT 'ACTIVE' CHECK (
                        status IN ('ACTIVE', 'CONTAINED', 'RESOLVED', 'FALSE_POSITIVE')
                    ),
    created_at      TEXT    NOT NULL DEFAULT (STRFTIME('%Y-%m-%dT%H:%M:%fZ', 'NOW'))
);

CREATE INDEX IF NOT EXISTS idx_incidents_status ON incidents (status);
CREATE INDEX IF NOT EXISTS idx_incidents_severity ON incidents (severity);

-- ─────────────────────────────────────────────────────────────
-- shield_actions — every containment action Shields has executed
-- ─────────────────────────────────────────────────────────────
CREATE TABLE IF NOT EXISTS shield_actions (
    id                  INTEGER PRIMARY KEY AUTOINCREMENT,
    incident_id         INTEGER NOT NULL REFERENCES incidents (id) ON DELETE RESTRICT,
    shield_type         TEXT    NOT NULL CHECK (
                            shield_type IN ('FIREWALL_DROP', 'PROCESS_KILL', 'QUARANTINE')
                        ),
    target_identifier   TEXT    NOT NULL,        -- IP address or PID, as text
    latency_ms          INTEGER,                  -- NULL while PENDING approval
    status              TEXT    NOT NULL DEFAULT 'COMPLETED' CHECK (
                            status IN ('PENDING', 'COMPLETED', 'FAILED')
                        ),
    executed_at         TEXT    NOT NULL DEFAULT (STRFTIME('%Y-%m-%dT%H:%M:%fZ', 'NOW'))
);

CREATE INDEX IF NOT EXISTS idx_shield_incident ON shield_actions (incident_id);

Design notes:

  • Every table uses CHECK constraints on its enum-like columns (status, severity, source_module, shield_type) instead of trusting the app layer alone — a malformed agent response or a typo in shields/ fails loudly at the DB, not silently.
  • incidents and shield_actions are append-only by convention: status changes (ACTIVE → CONTAINED) are UPDATEs on the status column only, never row deletion or rewriting of risk_score/summary/latency_ms after the fact — this preserves the audit trail the TRD requires.
  • shield_actions.status = 'PENDING' with latency_ms = NULL is how HUMAN_APPROVAL mode represents a queued-but-not-yet-executed action; the row is updated in place to COMPLETED + a real latency once a human clicks "Deploy Shield," rather than inserting a second row.
  • telemetry_events.correlated + the partial index lets the brain's consumer loop efficiently pull only unprocessed events without a full table scan as the log grows.

2. Python DAO Skeleton — database/manager.py

"""
database/manager.py — sole owner of all SQLite access for Project Ultron.

No other module opens a sqlite3 connection directly. Sensors, core/, shields/,
and ui/ all go through DatabaseManager's public methods.
"""

import queue
import sqlite3
import threading
from pathlib import Path
from typing import Any


class DatabaseManager:
    """Thread-safe SQLite access via a single dedicated writer thread.

    Reads: any thread may call a read method directly — each opens its own
    short-lived connection (WAL mode allows concurrent readers).
    Writes: never executed on the calling thread. Every write method builds
    a (sql, params) job and puts it on an internal queue; one dedicated
    writer thread drains that queue and is the only thread that ever holds
    a write connection. This sidesteps SQLite's "one writer at a time"
    limitation without callers blocking on locks themselves.
    """

    def __init__(self, db_path: str | Path):
        self._db_path = str(db_path)
        self._write_queue: queue.Queue[tuple[str, tuple, "queue.Queue | None"]] = queue.Queue()
        self._writer_thread: threading.Thread | None = None
        self._stop_event = threading.Event()

    # ── lifecycle ────────────────────────────────────────────────

    def init_db(self, schema_path: str | Path) -> None:
        """Run the DDL in schema.sql once at startup (idempotent —
        every CREATE TABLE/INDEX uses IF NOT EXISTS). Also sets
        PRAGMA journal_mode=WAL on the connection used to do so."""
        ...

    def start(self) -> None:
        """Spawn the dedicated writer thread (daemon=True) and begin
        draining self._write_queue in a loop."""
        ...

    def stop(self) -> None:
        """Signal the writer thread to finish its queue and exit cleanly
        (used on app shutdown)."""
        ...

    def _writer_loop(self) -> None:
        """Runs only on the writer thread. Opens ONE long-lived
        connection with check_same_thread=False (safe here because it's
        never touched from any other thread), pulls (sql, params, ack_q)
        tuples, executes + commits each, and puts the result/row id back
        on ack_q if the caller wants confirmation (e.g. new incident id)."""
        ...

    def _get_read_connection(self) -> sqlite3.Connection:
        """Opens a short-lived read-only connection for the calling
        thread. Safe under WAL because readers don't block the writer
        and vice versa."""
        ...

    # ── writes (queued, executed on writer thread) ─────────────────

    def upsert_network_asset(
        self, ip_address: str, mac_address: str, hostname: str | None,
        is_authorized: bool,
    ) -> None:
        """INSERT ... ON CONFLICT(ip_address) DO UPDATE SET last_seen=...,
        mac_address=..., hostname=... Queued as a fire-and-forget write."""
        ...

    def insert_telemetry_event(
        self, source_module: str, suspicious_ip: str | None, raw_payload: str,
    ) -> None:
        """Queued fire-and-forget write from sensor threads."""
        ...

    def mark_events_correlated(self, event_ids: list[int]) -> None:
        """Batched UPDATE telemetry_events SET correlated=1 WHERE id IN (...),
        called by core/correlator.py once a batch has been sent to the agent."""
        ...

    def log_incident(
        self, incident_uid: str, risk_score: int, severity: str,
        mitre_tactic: str | None, mitre_id: str | None, summary: str | None,
    ) -> int:
        """Queued write that WAITS for the writer thread's ack (via a
        one-shot ack queue) so it can return the new incident's row id —
        core/brain.py needs that id immediately to log the follow-up
        shield_actions row."""
        ...

    def update_incident_status(self, incident_id: int, status: str) -> None:
        """UPDATE incidents SET status=? WHERE id=?. Status-column-only
        update — never touches risk_score/summary after creation."""
        ...

    def log_shield_action(
        self, incident_id: int, shield_type: str, target_identifier: str,
        latency_ms: int | None, status: str = "COMPLETED",
    ) -> int:
        """Queued, ack-returning write (same pattern as log_incident) —
        the ui/ShieldLogFrame wants the new row id to update it in place
        if a PENDING action later completes."""
        ...

    def complete_pending_shield_action(self, action_id: int, latency_ms: int) -> None:
        """UPDATE shield_actions SET status='COMPLETED', latency_ms=?
        WHERE id=?. Used by the HUMAN_APPROVAL 'Deploy Shield' click path."""
        ...

    # ── reads (direct, short-lived connection per call) ─────────────

    def get_uncorrelated_events(self, limit: int = 100) -> list[dict[str, Any]]:
        """SELECT * FROM telemetry_events WHERE correlated=0 ORDER BY
        timestamp ASC LIMIT ?. Called by core/brain.py's consumer loop."""
        ...

    def get_all_assets(self) -> list[dict[str, Any]]:
        """For RadarFrame's initial population / periodic refresh."""
        ...

    def get_repeat_offender_count(self, ip_address: str, window_hours: int = 24) -> int:
        """COUNT of past incidents linked (via shield_actions.target_identifier
        or telemetry_events.suspicious_ip) to this IP within the window —
        feeds core/risk_scoring.py's heuristic."""
        ...

    def get_recent_incidents(self, limit: int = 50) -> list[dict[str, Any]]:
        """For IncidentDetail / natural-language case querying."""
        ...

    def get_shield_actions_for_incident(self, incident_id: int) -> list[dict[str, Any]]:
        ...

    def query_incidents_by_filter(
        self, status: str | None = None, min_severity: str | None = None,
        subnet_prefix: str | None = None, since: str | None = None,
    ) -> list[dict[str, Any]]:
        """Backing query for the UI's natural-language case search — the
        agent translates free text into these structured filter args
        (never raw SQL) before this method runs a parameterized query."""
        ...

3. Thread-Safe Write Handling

Two things make SQLite genuinely safe here, and it's important they're both in play rather than relying on either alone:

  1. WAL mode (PRAGMA journal_mode=WAL) lets any number of reader threads run concurrently with a single writer without blocking each other — this is why every get_* method above can open its own connection on whatever thread calls it (sensor threads, the UI poll loop, the brain thread) with no coordination needed.
  2. A single dedicated writer thread absorbs all writes. Even under WAL, SQLite still allows only one writer transaction at a time — if sensors/, core/brain.py, and shields/ all opened their own write connections and committed concurrently, you'd hit intermittent database is locked errors under load (exactly the kind of thing that looks fine in testing and then fails live on stage). Instead, every write method (upsert_network_asset, insert_telemetry_event, log_incident, log_shield_action, etc.) does no I/O itself — it just packages (sql, params) and puts it on self._write_queue, and only _writer_loop, running on its own thread with check_same_thread=False set safely (because no other thread ever uses that specific connection object), actually executes and commits. This turns SQLite's single-writer constraint into a non-issue instead of a race condition: writes are serialized by construction, not by hoping threads don't collide.
  3. Writes that need a result (log_incident, log_shield_action) pass a one-shot queue.Queue() back through the job tuple — the writer thread executes the insert, then .put()s the new row id on that ack queue, and the calling thread (e.g. core/brain.py, which needs the incident id right away to log the paired shield action) blocks briefly on ack_q.get(). This keeps the API synchronous-feeling for callers that need the id, while every other write stays pure fire-and-forget for maximum throughput from the sensor threads.
